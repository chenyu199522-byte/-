# 金羊毛

独立的 Windows 银行活动记录 App。首次打开是空白记录，无需注册。可以记录开户、工资直接存款（DD）、借记卡及信用卡消费、免月费条件、奖励到账、关户与再次参加资格。按期达标、工作日和到账日期沿用金羊毛既有规则。长期活动可分别记录收益、存入和提取。

## 下载使用

在 [Releases](https://github.com/chenyu199522-byte/-/releases/latest) 下载 Windows x64 压缩包，**完整解压到一个文件夹**后运行其中的「金羊毛.exe」。也可以下载安装程序创建快捷方式。两种方式在同一 Windows 用户下使用同一份记录。

1. 点击「新增奖励活动」，填入银行和活动条件，保存。
2. 在活动的「…」中选择「记录开户」，再用「管理 DD」或「按月核对」添加记录；一个窗口可同时添加多笔 DD、消费和存款余额。
3. 银行实际发奖后选择「奖励到账」。长期活动在「长期活动」中登记逐笔明细。

在记录窗口点「＋ 再加一笔」可添加不同类型、日期和金额，最多 100 笔，一次保存。新增行沿用上一行的类型、日期和备注，金额留空；任一笔有误时整批都不保存，修正后可重试。存款余额同一天只能保留一条，已有记录使用「修改金额」。

## 活动截图与推荐链接

在编辑活动的「参考与备注」中，点击「添加图片」可一次选择多张活动条款、客服沟通或关户截图。支持 PNG、JPEG、WebP、GIF 和 BMP，单张最多 25 MB。点击「保存奖励活动」后，原始图片会复制到本机数据目录。活动详情中可以查看截图、切换原始尺寸并导出原图。导出文件保留原始字节，图片上的文字也保留原样。

「推荐链接」位于「活动来源链接」旁，可记录自己的或他人的推荐链接。早期版本已有的关户来源会以原标签保留，方便回查。

## DD 条件与社区入口

首页「已归档」后方的「DD条件检测」，提供 NextBonus、BankRewards、BankBonus、BonusHQ、Churnables、Doctor of Credit、BonusClerk、BonusChurn、SuperChurn 九个网站入口，方便查阅条款和用户经验。

「论坛与指南」提供美卡论坛、美国信用卡指南及 Doctor of Credit 英文站。点击链接会在系统默认浏览器打开所选网站。

## 信用卡消费与 AI 辅助

记录类型支持工资 DD、借记卡消费和信用卡消费，三种金额分别累计。一次性 DD 可选择“累计总额”或“每笔金额达标”；累计总额也能同时要求最低笔数，例如累计 $5,000 且至少两笔，金额和笔数都满足才完成。旧记录保留原每笔计算含义，可在编辑活动中切换。每期可同时设置三项门槛，已设置的条件全部满足后才点亮该期；未设置的项目不显示进度条。信用卡消费也支持一次性活动的累计门槛，并可作为免月费累计项目。

在「DD条件检测 → AI 设置」添加自己的 AI 服务。使用 OpenAI 官方服务时，只需粘贴密钥并点击「连接并使用」，软件读取该密钥下的模型列表、选择模型，并发送一次简短请求验证，成功后加密保存。服务名称自动生成；需要切换时点击「更换模型」，从实际返回的列表选择，无需手写模型名称。模型列表受密钥权限影响，读取失败时仍可使用高级设置。

「其他服务 / 高级设置」保留多家配置：其他 OpenAI 兼容接口、Claude / Anthropic 和 Gemini，也可手动设置 OpenAI。这里填写服务名称、API 基础地址、准确模型 ID 和密钥，查询时选择一家。OpenAI 基础地址通常为 https://api.openai.com/v1，Claude 为 https://api.anthropic.com/v1，Gemini 为 https://generativelanguage.googleapis.com/v1beta。其他兼容服务按供应商说明填写；地址须为 HTTPS。

**活动自动填写**：点击「AI 一键填写」，粘贴银行公开活动详情链接。软件在隐藏、独立的网页环境中读取页面，将文字发送给所选模型。同页出现不同奖励方案时，分别展示金额和条件；点击想参加的那一档，填入新增活动表单，检查后保存。支持动态加载页面；需要登录或人工验证的页面可能无法读取。系统只填入能核对到原文的字段，其他字段留空。存款维持、合格交易笔数可独立追踪；未能结构化的限制保留在说明和备注中。存款持有期不作为账户安全关户天数。截图可另行添加作为留存。

**DD 来源查询**：在「已归档」后点击「DD条件检测」，可选单个活动、同一家银行的全部活动或所有活动。系统逐笔检查范围内的工资 DD（包含已归档活动，不包含消费和存款余额）。缺少来源备注时先集中补填、保存，再开始查询。逐笔展示结果；单笔失败不影响其余记录，可中途停止。查询九个参考网站及相关页面，展示原文依据、链接、查询时间和未能读取的网页。找不到同时匹配银行及来源的依据时显示「待核实」。资料互相矛盾会提示分歧，用户经验不等于银行确认，不会自动改动 DD 达标状态。OpenAI 类型使用原生联网搜索发现页面，再读取、校验引用；其他接口直接查阅参考网页。可选配置 Tavily 搜索密钥，增强具体银行与来源的站内检索。

AI 功能在用户连接服务、读取模型列表或发起查询时联网。发送范围是当前活动网页，或当前银行、活动说明和选定 DD 来源；不发送整本记录或截图。API 费用由用户自己的服务商收取。密钥通过 Windows 本机加密存入 ai-settings.json，不返回到页面显示，不含在发布包内；换电脑需重新填写。未配置 AI 时，手动记录、截图及网页入口均可使用。

## 多条件活动与规则提醒

活动主行保留银行、奖励和总进度。单项要求沿用原有展示；已有账户的多项条件在「DD 要求」列只显示「已在下方展示」，具体金额和进度放在第二排。分期活动主行用圆点和完成期数展示，每期全部条件达标后点亮；当前期标题以绿色显示剩余天数和状态。填有免月费金额门槛或免费期数就显示进度，未填写条件才隐藏。周期未配置完整时展示开户以来已记录金额，不判定本期达标；选好周期后按期计算。首页不额外显示设置提醒，三种周期仍在编辑活动中自行选择。其他多条件活动保留剩余时间，不重复展示 DD 金额和进度。编辑活动时选择“已开户”，填写实际开户日期后保存，即可建立账户；已有账户不会重复建立。存入截止日期、交易截止日期及倒计时各自展示在对应进度条下方，不再额外展开右侧规则栏。优惠码、月费说明、关户限制和其他条款可展开「补充说明」查看；尚有其他条件待核对时，折叠标题会提示。账户详情仍保留完整规则。

- **存款金额**：在存款进度下点击“添加存款记录”，或在“记录 DD”的类型中选择“存款余额”；填写指定日期的合格资金余额，显示已存金额 / 要求金额。“修改金额”预填最近一笔余额用于纠正；实际余额变化时应添加新记录以保留历史。余额沿用到下一次记录；工资 DD 不会自动增加这项余额。
- **持有时间**：可选择「存足后连续若干天 / 月」或「保持至开户后第几天」。支持固定开始日，例如开户后第 45 天至第 90 天。月份按日历月计算，不固定换算成 30 天。
- **倒计时**：显示进度、剩余天数及完成日期。未存足、期限未知或记录中途跌破余额门槛时不会自动标记成功。只有条款明确允许时，才选择跌破后重新计时。最终持有日当天仍须满足余额要求。
- **合格交易次数**：可选活动期间累计或每月 / 每期单独计算。按期支持自然月、账单周期和开户日逐月，独立于 DD 周期；每期分别统计，超额不结转。填写考核期数后须全部期数达标；不填则持续记录，不判定整项活动完成。独立记录每笔日期与说明，显示 0 / 6 笔等进度。超出截止日的交易保留但不计入完成；需要用户按银行定义确认合格，不把所有 DD 或消费自动当成合格交易。
- **其他条件**：不能由金额、时间、笔数代表的要求可单独填写，在账户中记录核对完成日期。
- **分项奖励**：同一活动若明确允许存款奖励与 DD 奖励叠加，可分别设置金额、分别记录实际到账；只到账一项时显示部分到账。互斥奖励档位应选择其中一档，不相加。
- **月底发奖**：支持「全部条件达标的当月月底」作为起算日，再计算自然日或工作日到账期限。

这些进度根据本机记录推算，不能证明银行认可资格；未记录的余额变动不会自动得知。账户实际数据仍需自行登记和核对。

## 窗口与布局

整体缩放沿用已有设置，新安装默认 100%；可手动开启按窗口可用宽高等比例缩放整个界面，以 1440×900 的内容区为参考，自动倍率为 85%–160%。到达下限后，窄窗口继续使用换行、精简列和局部滚动。Windows 显示缩放由系统先行处理。

在首页点「编辑布局」可以设置软件名称，首页和窗口标题会即时预览，保存后在下次启动继续使用。这里也可以切换自动缩放。原版模式按内容自动分配列宽，窄窗口在表格内横向滚动；拖动列宽滑块会切到自定义列宽，也可启用窄窗口精简列。页面可调整字号、外边距与区域间距。统计卡片可逐项显示、隐藏、换序和调整最小宽度。活动表格可调整行高、各列宽度与顺序，并选择显示哪些列。机构和操作入口始终可用。修改可即时预览，点击「保存布局」后在本机生效；「取消」放弃本次修改。「恢复默认」也需要保存才会生效。

默认在窄窗口优先展示主要列，可在表格底部点「显示全部列」，并横向滚动查看。也可以在布局编辑器关闭自动精简。一次性活动、长期活动与记录表单共用字号设置。设置单独保存在 `%APPDATA%\GoldenFleeceRecords\layout.json`。

## 本机记录与备份

数据保存在 `%APPDATA%\GoldenFleeceRecords\records.json`。第一笔记录保存后才会创建文件。换电脑或做完整备份时，退出 App，再复制这个文件及同目录下的 `images` 文件夹。恢复时，先备份目标电脑原有文件，再将备份放到相同位置。`records.json` 保存活动、账户、DD、消费、规则及长期明细，`images` 保存原始截图。一起备份、恢复这两项即可保留图片关联。个人名称和布局保存在同目录的 `layout.json`，迁移时可以一起复制。界面上的 CSV 适合查看摘要。

分享发布页的压缩包或安装包即可。每位使用者独立记录，App 没有银行登录、远程同步或自动拉取银行流水功能。

## 从源码构建

Windows x64、Node.js 22.12+ 和 npm。在仓库目录依次运行：

```sh
npm ci
npm test
npm run package:win
npm run test:desktop
npm run test:layout
npm run test:features
npm run test:ai
npm run test:deposit
```

公开程序没有测试模式入口或内置示例记录。开发者自动化测试使用隔离的合成数据。

发布文件在 `release/`。桌面验收使用临时数据目录、合成记录和隐藏窗口。
